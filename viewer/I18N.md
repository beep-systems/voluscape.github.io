# Custom UI localization

All custom UI strings are maintained in [locales/en.js](locales/en.js), including
icon hints, accessible labels, placeholders, statuses, calibration messages,
dialog text, palette names and generated reference names. Edit the value of a
key and reload the page; no npm installation, bundle patch or rebuild is needed.
Keep keys stable when changing wording.

Only English is shipped. The page chooses its language once at startup:

- `http://127.0.0.1:4173/?lang=en` explicitly selects English.
- Missing or unsupported language selects `en`; browser preferences are ignored.
- Tags match without case sensitivity, first exactly, then by their base language.
  For example `EN-us` resolves to `en`.

The resolved locale sets the page's `lang` and is passed to SuperSplat's existing
`lang` option. SuperSplat keeps its own translations in the source fork. Custom
translation changes do not modify the fork or vendor bundle. This stage has no
language selector or switching without page reload.

## Add a language

1. Add an ES module such as `locales/de.js`, exporting an object of string values
   with the same keys as English. Partial dictionaries fall back to English for
   missing keys. Use a valid BCP 47 tag for the locale name.
2. Import the dictionary and register it in `locales` in [i18n.js](i18n.js).
3. Add its exact filename to `publicFiles` in `scripts/serve.mjs`. Keep the server
   allowlist explicit.
4. Open `?lang=de` and verify hints, forms, dialogs, number formatting and the
   upstream controls. The upstream viewer must also support that language to
   display its own UI in the same language.

Named placeholders use `{filename}`, `{count}`, `{distance}`, etc. Retain each
placeholder when translating. The renderer inserts values as plain text, not
HTML. There is no HTML markup or plural-expression syntax in dictionary strings.

## Bind custom UI text

Static text uses `data-i18n="marker.name"` on a dedicated text element. Icon
buttons use `data-i18n-title`, `data-i18n-aria-label`; inputs use
`data-i18n-placeholder`. Never put `data-i18n` on an element whose children must
survive, such as an SVG icon button. `applyTranslations(root, i18n)` updates text
and only the supported attributes. Dynamic values use `i18n.t(key, params)`:

```js
const { t, formatNumber } = i18n;
button.title = t('scene.closeFileHint', { filename });
summary.textContent = t('scale.routeLength', {
  distance: formatNumber(totalMeters, 2)
});
```

`createI18n(lang)` returns `{ locale, t, formatNumber }`. Unknown keys fall back
to the key itself for debugging; missing parameters remain visible placeholders.
`formatNumber(value, digits = 0)` uses the resolved locale, a fixed number of
fraction digits and no thousands separators. Measurement values in snapshots
remain numbers; distance input continues to accept either dot or comma.

`SceneController` accepts an optional `i18n`, defaulting to the English instance:

```js
const i18n = createI18n('de');
const controller = new SceneController(host, { createViewer, settings, i18n });
```

An embedding host can supply its own registered dictionaries through the optional
second argument to `createI18n(lang, dictionaries)`. This is also how tests verify
a second language without shipping another locale. Treat an instance's locale as
fixed throughout the controller lifetime. Event and measurement snapshot shapes
are unchanged. Own error messages are localized; external engine details remain
in the existing diagnostic `cause`.

User names, notes and filenames are content and are never translated. Default
reference names are generated in the selected language, then stored as regular
marker names. Existing IDs, enum values, anchors and scale values are unchanged.
The exported `markerPalette.name` retains its English value for API compatibility;
the page uses `color.<id>` in its selected locale.

## Checks

Run `npm test` and `npm run test:i18n` from the viewer directory. The latter uses
the same Playwright/Chromium setup as the existing browser checks and a test-only
dictionary intercepted in the browser. Reports are written to ignored
`build/viewer-i18n-browser/`. For release verification also run the five existing
browser suites. Vendor-update validation includes the localization browser suite.
Synthetic checks do not establish physical-phone or reconstruction quality.
